# OCR API 후보 비교

PRD §6 OCR 판정에 쓸 영수증 특화 OCR API를 조사한다. 판단 기준은 세 가지: ①금액·상호·결제일·**승인번호**를 필드 단위로 주는지(승인번호가 `DUPLICATE` 판정의 근거, PRD §8 유니크 인덱스 `ocr_approval_no+ocr_paid_at+amount`) ②무료 한도·요금 ③한국어 영수증 정확도. 일반 OCR(Tesseract 등)은 한국어 영수증 정확도가 부족해 후보에서 제외한다.

## 비교표

| 후보 | 필드 단위 추출 | 한국어 영수증 정확도 | 무료 한도 |
| --- | --- | --- | --- |
| **네이버 CLOVA OCR** (General 도메인, **실측 완료**) | 이름표 붙은 key-value는 안 오지만, **각 텍스트마다 좌표(`boundingPoly`)가 딸려 있고 표 영역은 `tables`로 행·열 구조까지 잡아준다.** "라벨 근처 좌표에 있는 다음 텍스트"를 값으로 잡는 방식으로 뽑아낼 수 있다 (아래 5번 항목) | **실제 영수증 2장 테스트 결과 정확함** — 금액·날짜·승인번호 숫자는 전부 정확히 인식(신뢰도 0.99대). 주소 일부("충청남도"→"중청남도")에서만 오탈자 1건 | 글자추출 100건/월 무료, 도메인 자체 고정요금 없음 (초과분 단가는 콘솔에서 별도 확인 필요) |
| **Upstage Information Extract** | 스키마를 직접 정의하는 방식 — "승인번호" 등을 필드명으로 지정하면 그 키로 바로 받을 수 있음(미실측) | 실측 검증 안 함 | 콘솔 가입 후 확인 필요 |
| **AWS Textract — AnalyzeExpense** | 미국식 인보이스/영수증 스키마 위주. 한국 카드 승인번호 대응 불투명 | 해외 벤더, 한국어 영수증 학습 데이터 상대적으로 부족할 가능성 | 월 100페이지 무료(신규계정 3개월), 이후 페이지당 과금 |

## 결론

**CLOVA OCR로 간다.** 실제 영수증 2장(CU 편의점, 던킨도너츠)으로 테스트한 결과 텍스트 인식 정확도가 충분히 좋았고, 특히 승인번호·금액처럼 숫자로 된 값은 전부 정확했다. 무료 한도도 이번 학기 데모 용도로는 충분하다.

**"필드 단위로 이름표 붙여서 준다"는 원래 기대와는 다르게 동작하지만, 처음 생각했던 것보다 훨씬 쓸만하다.** 실제 API 응답(JSON) 원본을 받아서 확인한 결과:

- **`tables`** — 영수증의 상품 목록처럼 표로 보이는 영역은 CLOVA가 알아서 행·열(`rowIndex`/`columnIndex`)로 구조화해서 준다. "청정원)연겨자35g / 1 / 2,000"이 이미 한 행으로 묶여서 나옴
- **`fields`** — 표가 아닌 부분(매장정보·결제정보 등)은 이름표(`승인번호:`)와 값(`39007018`)이 **각각 별도 항목이지만, 둘 다 좌표(`boundingPoly`)를 갖고 있다.** 실제로 "승인번호:" 항목의 우측 바로 옆(x 좌표가 이어짐, y 좌표는 거의 같음)에 "39007018"이 붙어있는 걸 확인함 — 좌표 기준으로 "라벨 오른쪽/같은 줄에 있는 다음 텍스트"를 값으로 잡으면 신뢰도 높게 추출 가능
- **`inferConfidence`** — 단어 하나하나마다 인식 신뢰도가 딸려 나온다(승인번호 라벨 0.9977, 값 0.9998). PRD §6의 `UNREADABLE` 판정을 이 신뢰도 임계값으로 구현할 수 있다는 뜻 — 별도 규칙을 새로 만들 필요 없이 CLOVA가 이미 주는 값을 쓰면 됨

즉 우리가 짤 파싱 로직은 "텍스트 전체에서 정규식으로 찾기"가 아니라 **"좌표 기반으로 라벨-값을 짝짓기"**가 더 정확한 접근이다. 실제 응답 예시를 `docs/samples/clova_ocr_response_example.json`에 저장해뒀다 — 나중에 이 로직을 구현할 사람이 실제 구조를 눈으로 보고 짤 수 있게.

## 실측 기록

| | CU 편의점 | 던킨도너츠 |
| --- | --- | --- |
| 인식된 승인번호 | `39007018` (신뢰도 0.9998) | `31008018` |
| 인식된 결제금액 | `4,600` | `7,600` |
| 인식된 날짜 | `2026-09-18` | `2026-09-18 13:30:48` |
| 오류 | 없음 | 주소 "충청남도"→"중청남도" 오탈자 1건 (승인번호·금액엔 영향 없음) |
| 표 구조(`tables`) 인식 | 상품 2줄 + 합계 3줄, 총 6행 모두 정확히 행 단위로 구조화됨 | 미확인 (이번 JSON은 CU 영수증만) |
